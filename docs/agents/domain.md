# Domain Docs

Web・API 共通で、単一の用語集と設計判断の記録を使う。

## 作業前に参照するもの

- ルートの CONTEXT.md: ドメイン用語の定義
- docs/adr/: 対象の作業に関係する設計判断

これらが存在しなくても、そのまま作業を進める。
不在を問題として報告したり、空のファイルを先に作ったりしない。
domain-modeling が、用語や判断が確定した時点で必要に応じて作成する。

## 用語の統一

Issue・コード・テスト・説明では、CONTEXT.md の用語を使う。
未定義の用語が必要になった場合は、既存の用語で表せないか確認し、
必要なら domain-modeling で定義する。

## 設計判断との整合

既存の ADR と矛盾する提案は、該当する ADR と見直す理由を明示する。
既存の判断を黙って上書きしない。
