# Spot Finder

地図を動かし、指定した半径内のスポットを探せるWebアプリです。検索結果を地図と一覧で表示し、移動中も地図中心の住所を更新します。

## 環境構築

必要なものは **Docker（Compose v2以降）** と **Google MapsのAPIキー** です。ホストへのNode.js・pnpmのインストールは不要です。

```sh
git clone https://github.com/otaki0413/spot-finder.git
cd spot-finder
cp .env.example .env
```

Google Cloudで請求先を設定し、以下の2つのAPIを有効にしてください。

| API                 | 用途                                       |
| ------------------- | ------------------------------------------ |
| Maps JavaScript API | 地図・番号付きマーカー・検索半径の円を表示 |
| Geocoding API       | 地図中心の緯度・経度から住所を取得         |

ブラウザ用APIキーを作成し、以下を設定してください。

| 設定                       | 内容                                                     |
| -------------------------- | -------------------------------------------------------- |
| `.env`                     | `GOOGLE_MAPS_API_KEY` にブラウザ用APIキーを設定          |
| キーのアプリケーション制限 | 「ウェブサイト」を選び、`http://localhost:3000/*` を追加 |
| キーのAPI制限              | 上記2つのAPIのみ許可                                     |

> APIキーを含む `.env` はGit・Dockerイメージに含めません。

Apple SiliconではPostGISイメージをエミュレーションで実行するため、初回起動に時間がかかる場合があります。

## 実行手順

Dockerを起動した状態で、リポジトリのルートから実行します。ポート3000・3001を使用します。

```sh
docker compose up
```

**[アプリを開く](http://localhost:3000)** — 東京駅を中心に、半径5kmのスポットが表示されます。

起動後は次の操作で確認できます。

| 操作                     | 確認できること                                             |
| ------------------------ | ---------------------------------------------------------- |
| 地図を動かす             | 移動中に中心の住所が更新され、停止すると周辺スポットを検索 |
| 半径を入力してEnter      | 円・マーカー・一覧が同じ条件で更新。小数も指定可能         |
| 一覧を見る               | 半径内のスポットを中心点から近い順に表示                   |
| スポットのない場所へ移動 | 0件の案内を表示                                            |

停止は `Ctrl+C`、コンテナの削除は `docker compose down` です。DBデータは保持されます。設定変更やDB再作成の手順は [開発・検証ガイド](docs/development.md) にまとめています。

## 使用した主要ライブラリとその選定理由

Next.js（App Router）・Tailwind CSS・NestJS・TypeORM・PostgreSQLは課題指定の技術です。追加で採用した主な技術は以下のとおりです。

| 技術                                      | 選定理由                                                                      |
| ----------------------------------------- | ----------------------------------------------------------------------------- |
| Google Maps / `@vis.gl/react-google-maps` | 地図表示と住所取得を同じ提供元に揃え、地図とReactの状態を連携しやすくするため |
| TanStack Query                            | 検索条件ごとのキャッシュ、通信の中断、取得状態をまとめて管理するため          |
| PostGIS                                   | 地表上の距離による半径検索と空間インデックスを利用するため                    |

## 実装時に特に工夫した点、および技術的な判断を行った箇所

- **データ取り込み時の整合性**：CSVの取り込みは単一トランザクションで行い、途中で失敗した場合に一部のデータだけが残らないようにしました。取り込みはDBの初期化時のみ実行し、通常の再起動では既存のデータとIDを保持します。
- **PostGISによる距離の判定**：半径検索にはPostGISのgeography型を使い、地表上の距離で判定しています。指定半径の境界にあるスポットも含め、中心点から近い順に返します。
- **検索タイミングとキャッシュ**：スポット検索は地図の停止時と検索半径の変更時に実行します。同じ中心座標・半径の検索結果は5分間再利用します。また、条件が変わった際は実行中の検索を中断し、古い応答で表示が戻らないようにしています。
- **地図移動中の住所更新**：地図を動かしている間も中心地点を把握できるよう、住所取得は最大1秒に1回行います。新しい問い合わせを開始した後は、それ以前の応答を反映しません。停止後も最後の中心地点の住所が表示されるようにし、住所の履歴キャッシュは作っていません。

なお、課題本文ではスポットデータは「約500件」とありますが、提供CSVに含まれる200件をそのまま使用しています。

サービス選定時の比較や理由は、[PostGISのADR](docs/adr/0001-use-postgis-for-spot-locations.md)と[地図サービスのADR](docs/adr/0002-map-and-geocoding-services.md)にまとめています。

## 時間が足りず実装を簡略化した箇所や、今後の改善点

- **わずかな移動での住所取得**：取得間隔は制限していますが、移動距離による判定は入れていません。一定の距離を移動するまで再取得しない方式にすると、APIの呼び出し回数をさらに減らせます。ただし、表示する住所と地図中心のずれをどこまで許容するか検討が必要です。
- **住所候補の選択**：逆ジオコーディングで返された先頭候補をそのまま表示しています。候補の種類を見て、地図の中心地点を把握しやすい住所を選ぶ余地があります。
- **マーカーと一覧の選択連動**：地図と一覧には同じ検索結果を表示していますが、クリックした項目を相互に強調する機能はありません。追加の改善として、一覧で選んだスポットの位置を地図上でも確認しやすくしたいと考えています。
